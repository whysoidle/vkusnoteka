# Вкуснотека

Нативное приложение для Android, Windows и macOS на Flutter. На Mac — боковая панель, полупрозрачные панели и нативный Liquid Glass на macOS 26+; на более ранних версиях — системный материал окна. Интерфейс Material 3: системная палитра на поддерживаемых Android, светлая и тёмная темы, скруглённые карточки, нижняя навигация на телефоне и каталог рядом с чатом на широком экране.

Готовые файлы: Android **1.0.2** — `dist/Vkusnoteka-Android-1.0.2.apk`; macOS **1.0.5** — `dist/Vkusnoteka-macOS-1.0.5.dmg` и ZIP с приложением. Windows **1.0.6** — `dist/Vkusnoteka-Windows-1.0.6-Setup.exe` и portable ZIP; собраны на Windows-сервере GitHub Actions. [Результаты проверок](docs/validation.md).

Версия **1.0.6** встраивает локальный ИИ в Windows: CPU-движок llama.cpp и загрузка Qwen3 4B из настроек. Общие проверки исходного текста не дают переносить количество от соседнего ингредиента, отбрасывают посуду и разделяют короткие видео при переходе к следующему рецепту. На Windows CI проверено настоящее распознавание моделью, включая неизвестные количества и два разных рецепта. [Описание выпуска](docs/release-1.0.6.md).

Версия **1.0.5** возвращает мягкую матовость заднего фона macOS: на macOS 26+ общий слой Liquid Glass использует вариант `regular`. Ровная заливка без диагональных полос и размытие прокручиваемого каталога под шапкой сохранены. [Описание выпуска](docs/release-1.0.5.md).

Версия **1.0.4** убирает диагональные полосы больших стеклянных поверхностей macOS. Закреплённая панель «Моя книга» расположена поверх каталога: при прокрутке карточки и текст заходят под неё и размываются без сохранения резких контуров. Интерфейсы Android и Windows сохранены. [Описание выпуска](docs/release-1.0.4.md).

Версия **1.0.3** обновляет только оформление macOS: прозрачный фон окна, нативный clear Liquid Glass над системным материалом рабочего стола, более прозрачные панели со светлыми кромками и мягкими тенями. Нативное стекло следует выбранной теме. Страницы сохраняют непрозрачную защиту в первом кадре перехода, затем открывают стеклянный фон; предыдущий экран не просвечивает. Системные «Уменьшение прозрачности» и «Уменьшение движения» учитываются. Интерфейсы Android и Windows сохраняют прежнее оформление. [Описание выпуска](docs/release-1.0.3.md).

Версия **1.0.2** переименовывает приложение в «Вкуснотеку» и добавляет выбранную стеклянную книгу: системные иконки Android, Windows и macOS, логотип в интерфейсе, адаптивная и монохромная иконки Android. Идентификаторы, пути к базе, облачная папка и хранилище паролей сохранены для обновления существующей установки. Техническое поле Windows `ProductName` остаётся прежним: от него зависят пути базы и зашифрованных паролей. [Описание выпуска](docs/release-1.0.2.md).

Версия **1.0.1** исправляет передачу системной инструкции LiteRT-LM на macOS и улучшает общий импорт YouTube: связные фрагменты автосубтитров, проверка названий и произнесённых количеств, отдельные карточки для опубликованных вариантов рецепта и привязка шагов по подтверждённым пропорциям. Ингредиенты могут извлекаться только из субтитров; описание не обязательно. [Проверка распознавания](docs/release-1.0.1.md).

Версия **1.0.0** объединяет исправления ресурсов на трёх ОС: отменяемый HTTP-импорт с лимитом ответа, освобождение обработчиков отмены и загрузки модели, остановку синхронизации при закрытии контроллера, очистку Android-обработчиков, тайм-аут Windows OCR и освобождение временных объектов macOS. Python-сервис также обновлён до 1.0.0. [Отчёт о выпуске и памяти](docs/release-1.0.md). Обновление **0.4.2** добавляет плавные macOS-анимации: раскрытие панели импорта, появление страниц на непрозрачном фоне, подсветку навигации, наведение и нажатие карточек, раскрытие фильтров и отклик избранного. Системное «Уменьшение движения» применяется на лету. Обновление **0.4.1** исправляет macOS-интерфейс: «Импорт рецепта» открывает отдельную область ввода даже в широком окне, а переходы в настройки и другие страницы происходят сразу, без показа предыдущего экрана. Обновление **0.4.0** добавляет универсальную macOS-сборку для Apple Silicon и Intel, локальный LiteRT-LM, русский OCR через Apple Vision, горячие клавиши и стеклянное оформление. Формат базы общий со всеми платформами. Обновление **0.3.2** исправляет прокрутку поверх текста и повторное декодирование фотографий, добавляет звуковой сигнал таймера на Android. В режиме готовки доступны проверка звука и остановка сигнала; громкость регулируется как у будильника. Версия **0.3.1** добавляет подключение Яндекс Диска через WebDAV. Версия **0.3.0** добавляет автоматические настройки, исправляет смену темы и скрытие клавиатуры при прокрутке. Доступны 8 основных цветов и цвета устройства, вход Яндекс OAuth, импорт фото/скриншотов/PDF, защита от дубликатов, пересчёт порций, режим готовки, фото блюда, теги и подборки. Локальный LiteRT-LM и исправление кодировок сохранены. Установите новый APK поверх предыдущего, не удаляя приложение. Для новых фото и тегов обновите исходники Windows-приложения до этой же версии.

## Возможности

- Чат принимает текст и ссылки. Перед сохранением открывается редактируемая карточка.
- Текст разбирается офлайн. Сайты с `Schema.org/Recipe` и опубликованное описание YouTube извлекаются прямо на устройстве.
- Android, Windows и macOS получают доступные субтитры YouTube напрямую и разбирают их локальной моделью. Android/macOS используют LiteRT-LM и Qwen3 1.7B INT4; Windows с версии 1.0.6 — встроенный llama.cpp и Qwen3 4B Q4_K_M (2,50 ГБ, скачивается в настройках). Python-сервис с Ollama остаётся альтернативой при выключенном локальном ИИ. [Устройство Windows ИИ и правила разбора](docs/release-1.0.6.md).
- Карточка содержит название, ингредиенты, нумерованные шаги, время, порции, категорию, заметки и ссылку на источник.
- Если рецепт недоступен, ссылка остаётся в карточке: её можно заполнить вручную или сохранить черновиком. Редактор не позволяет случайно удалить исходную ссылку.
- Каталог: поиск по названию, ингредиентам и заметкам, категории, избранное, черновики. В ингредиентах можно ставить отметки во время готовки.
- Android принимает текст и ссылки через системное меню «Поделиться».
- Локальная книга работает без интернета; общая база синхронизируется через Яндекс Диск.
- Экспорт и импорт `recipes.json` объединяют изменения, включая удаления и конфликтующие правки.

## Яндекс Диск

С версии **0.3.1** основной способ — **WebDAV с паролем приложения**, без регистрации OAuth-клиента и проверки разработчика через Госуслуги. В Яндекс ID → Безопасность → Пароли приложений создайте пароль типа «Файлы WebDAV». В настройках всех устройств введите логин одного аккаунта, отдельный пароль WebDAV и одинаковую папку `/RecipeVault`. Поля сохраняются автоматически. Нажмите «Проверить подключение», затем «Синхронизировать».

По [актуальной справке Яндекса](https://www.yandex.ru/support/yandex-360/customers/disk/web/ru/webdav) WebDAV доступен в тарифах Яндекс 360. Обычный пароль аккаунта не подходит. Пароль WebDAV хранится в защищённом хранилище ОС и не входит в настройки или файл базы; логин хранится только в локальных настройках. Сервер фиксирован на HTTPS, перенаправления с паролем запрещены. [Подробная инструкция](docs/yandex-webdav.md).

Действующие OAuth-подключения сохраняются при обновлении, а неподключённые установки переходят на WebDAV. Новый файл публикуется после полной загрузки через MOVE. Синхронизация с реальным аккаунтом пока не проверялась. Для личной книги и синхронизации собственный сервер не нужен.

В облаке хранится один основной файл `/RecipeVault/recipes.json`. Служебная папка `.devices` содержит по одной восстанавливаемой копии на устройство. Они нужны потому, что обычная загрузка файла в REST API Яндекс Диска не обеспечивает атомарного сравнения версий: при одновременной загрузке общий файл временно может отражать только одну из веток. Следующая синхронизация объединяет копии всех устройств.

Каждая карточка имеет стабильный UUID и вектор версий устройств. Последовательное изменение заменяет предыдущую версию; при независимом изменении одной карточки сохраняются обе версии, одна с подписью «копия при конфликте». Удаления хранятся как отметки, поэтому старое устройство не возвращает давно удалённый рецепт. Одновременное удаление и редактирование сохраняет редактируемую карточку; повторное удаление после объединения удалит её окончательно из каталога.

Синхронизация запускается после изменения, при возвращении в приложение и раз в три минуты, пока оно открыто. Есть ручная кнопка облака. Фоновая работа при закрытом приложении пока не реализована. Не удаляйте `.devices` или отметки удаления из JSON, если хотите сохранить историю синхронизации.

## Запуск приложения

Нужен Flutter **3.47.6** и JDK 21; точные зависимости приложения закреплены в `app/pubspec.lock`.

```bash
cd app
flutter pub get
flutter run
```

Для Windows также нужны Visual Studio с workload **Desktop development with C++** и Windows SDK. Android собирается на Windows, Linux или macOS с Android SDK. Windows приложение собирается на Windows: [требования Flutter](https://docs.flutter.dev/platform-integration/windows/setup).

### APK

Из корня проекта можно создать собственную подпись, чтобы последующие APK обновляли существующую установку:

```bash
python scripts/init-signing.py
cd app
flutter build apk --release
```

APK: `app/build/app/outputs/flutter-apk/app-release.apk`. Бережно храните `.local-signing/recipe-vault.p12` и `app/android/key.properties` — они исключены из Git. Если их нет, сборка использует отладочную подпись и подходит для тестирования; ключ такой сборки между машинами CI не стабилен.

Разрешите установку APK для приложения, из которого открываете файл. Приложение поддерживает Android 7 / API 24; локальный ИИ включается на Android 8+ с процессором ARM64. Установку и работу модели на реальном устройстве требуется проверить. Рабочие версии Android SDK и NDK определены Flutter.

### macOS

Откройте `dist/Vkusnoteka-macOS-1.0.5.dmg` и перетащите **Вкуснотека** в **Applications**. При обновлении сначала закройте старое приложение; после установки можно перенести прежний `RecipeVault.app` в Корзину, сохранив данные приложения. Затем откройте «Вкуснотеку». Сборка универсальная: Apple Silicon и Intel, macOS 12+. Нативный Liquid Glass включается на macOS 26+, раньше используется NSVisualEffectView. Настройки «Уменьшение прозрачности» и «Уменьшение движения» применяются на лету. Анимации занимают 160–320 мс; при уменьшении движения панели и страницы принимают конечное состояние сразу. Фото и текст карточек остаются на читаемом фоне.

В настройках задайте тот же аккаунт WebDAV и папку `/RecipeVault`, что на телефоне. Пароль хранится в системной Связке ключей, база — локально в контейнере приложения и на Яндекс Диске. Тему и основной цвет можно менять без перезапуска. **⌘ N** создаёт рецепт, **⌘ F** переводит фокус в поиск, **⌘ ,** открывает настройки, **⌘ 1 / ⌘ 2** переключают каталог и импорт. «Импорт рецепта» открывает отдельную область чата и переводит фокус в поле ввода. В каталоге широкого окна чат также доступен справа. При переключении режима и изменении ширины окна сохраняются набранный текст и сообщения.

На Mac изображения и сканы PDF распознаются локально через Apple Vision. Если системный OCR не поддерживает русский язык, приложение предлагает обновить macOS или заполнить рецепт вручную. LiteRT-LM 0.18.0 использует CPU и ту же отдельно скачиваемую Qwen3 1.7B INT4 (977 МБ). Приложение с моделью занимает около 1,2 ГБ без растущего каталога. Субтитры должны быть доступны у видео; отсутствующие ингредиенты модель достоверно восстановить не может.

Для повторной сборки нужен полный Xcode 26+ с принятой лицензией и Flutter 3.47.6. CocoaPods не нужен: плагины и LiteRT-LM подключены через Swift Package Manager.

```bash
./scripts/build-macos.sh
# Если flutter отсутствует в PATH:
FLUTTER_BIN=/путь/к/flutter/bin/flutter ./scripts/build-macos.sh
```

Сценарий создаёт `.app`, DMG, ZIP и контрольные суммы в `dist`. Для личной установки применяется локальная подпись; публичное распространение с нотариализацией Apple требует Developer ID. [Подробности проверки](docs/validation.md).

### Установщик Windows

Готовый установщик 1.0.6 находится в `dist/Vkusnoteka-Windows-1.0.6-Setup.exe`; portable-версию нужно распаковать целиком и запустить `recipe_vault.exe`. Для локального ИИ нужны Windows 10 версии 1903 или новее либо Windows 11, x64. [Повторная сборка через GitHub и доступ из VS Code](docs/windows-github.md).

Установите [Inno Setup 6](https://jrsoftware.org/isinfo.php), затем из корня проекта в PowerShell:

```powershell
./scripts/build-windows.ps1
```

Сценарий собирает приложение, добавляет библиотеки Visual C++ и создаёт `dist/Vkusnoteka-Windows-Setup.exe`. Установка выполняется для текущего пользователя. Удаление приложения не удаляет локальную книгу. Установщик не имеет коммерческой цифровой подписи.

`.github/workflows/build.yml` содержит проверки и сборки APK, EXE и macOS DMG в GitHub Actions. Загрузите проект в свой репозиторий и выполните **Build Android, Windows and macOS**. В **Run workflow** выберите `platform: windows` для EXE или `all` для всех платформ. Windows-артефакт содержит установщик с номером версии, portable ZIP и SHA-256. Сборки находятся в **Artifacts**. Для постоянной подписи Android задайте секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`. Никакие файлы или репозиторий автоматически не публикуются.


## Возможности 0.3.0

- Настройки применяются сразу. Поля подключения автоматически сохраняются через 450 мс после ввода и при уходе со страницы; незавершённые адреса и пути не заменяют последнюю корректную настройку. Тема и основной цвет меняются без закрытия экрана. Явно выбранный цвет используется вместо палитры обоев.
- Клавиатура скрывается при прокрутке каталога, чата, карточек, редактора и настроек, а также при отправке рецепта.
- **Яндекс Диск:** кнопка входа, статус подключения и синхронизации, время последней синхронизации, повторная попытка, отключение. Одна регистрация OAuth-приложения и публичный Client ID необходимы для личной сборки: [инструкция](docs/yandex-login.md). Секретный ключ не встраивается, вход использует PKCE. Реальное подключение аккаунта пока не проверялось.
- **Импорт документа:** кнопка скрепки в чате принимает JPG/PNG/WebP/BMP/PDF, на Android доступна камера. Русский и английский OCR на Android работает офлайн через Tesseract; на Windows используется штатный WinRT OCR, для которого нужен русский языковой пакет OCR. PDF читается через PDFium; страницы без текстового слоя распознаются как изображения. Максимум файл 50 МБ, до 20 выбранных страниц PDF за один импорт, текст 50 000 символов. Диапазон страниц показывается явно. Распознанный текст можно исправить до разбора; исходный текст, имя документа и указанная ссылка сохраняются, в том числе при отказе разбора.
- **Дубликаты:** сравниваются источник (включая разные ссылки на одно YouTube-видео), название и совпадение ингредиентов. При сохранении предлагается обновить существующий рецепт, сохранить отдельный или отменить. При обновлении сохраняются избранное, фото, теги, подборки, заметки и разделы, которых нет в новом импорте. Сравнение похожих названий является эвристикой.
- **Порции:** кнопки в карточке пересчитывают явные количества, десятичные числа, дроби и диапазоны. Исходный рецепт не меняется, есть сброс. Значения «по вкусу» и неизвестные количества не пересчитываются; неподтверждённые количества отмечены значком проверки.
- **Режим готовки:** один шаг, крупный текст, переходы, таймеры из длительностей в шаге и ручные таймеры. Отсчёт сохраняется при переходе между шагами; можно удерживать экран включённым. На Android по окончании звучит серия сигналов в течение 6,5 секунды через громкость будильника; сигнал можно остановить. На Windows и macOS используется системный звук предупреждения. Есть кнопка проверки звука. Это таймер внутри открытого режима: при выходе таймеры и звук сбрасываются, системные уведомления после закрытия приложения не добавлены.
- **Каталог:** фото блюда, пользовательские теги и подборки, включая «На каждый день», «До 30 минут», «Хочу приготовить»; фильтры по времени, наличию и отсутствию ингредиентов. Фото сжимаются в миниатюры JPEG до 120 КБ и хранятся в общей базе, поэтому доступны обоим устройствам после синхронизации. Прежний предел общей базы 20 МБ сохраняется.

APK с OCR и PDF около 158 МБ; локальная модель 977 МБ. Вместе около 1,14 ГБ, с запасом до 2 ГБ. Каталог рецептов и данные Android занимают дополнительное место.

## Локальный ИИ на Android, Windows и macOS

1. Установите приложение для своей ОС и откройте **Настройки → Локальный ИИ → Скачать модель**. На Windows нужен выпуск 1.0.6 или новее.
2. Дождитесь скачивания и проверки целостности. Нужны интернет и желательно 1,5 ГБ свободного места на Android/macOS или 3,5 ГБ на Windows; предпочтителен Wi-Fi. Прерванная загрузка продолжается с сохранённой части при повторном нажатии.
3. Оставьте **Использовать локальный ИИ** включённым и отправьте ссылку YouTube в чат; настройки применяются автоматически. При недоступных субтитрах можно вставить их текст вручную.

Движок: [Google LiteRT-LM](https://developers.google.com/edge/litert-lm/android), Android-зависимость закреплена на **0.18.0**. Начальная модель — [Qwen3 1.7B INT4, конверсия LiteRT community](https://huggingface.co/litert-community/Qwen3-1.7B): динамическая INT4, рабочий контекст 4096 токенов, 977 184 032 байта, лицензия Apache-2.0. Ревизия `73fbc3fe8271c162a603ee66f6e7ed25b6211195`; SHA-256 `2eeffef7b51bc3e1225ea69fe7aa5f417397934b56a5b6c20cc068d6fd2c918b`. APK не содержит веса модели и не требует Hugging Face токена. APK и модель вместе занимают около 1,14 ГБ; по размеру APK и распакованных файлов остаётся более 800 МБ запаса до 2 ГБ. Это оценка без растущего каталога рецептов и системных данных Android. Временный кеш LiteRT-LM удаляется после импорта. При замене модели старые веса удаляются до загрузки новых; готовая модель повторно не скачивается.

На Windows встроен [llama.cpp b11429](https://github.com/ggml-org/llama.cpp/releases/tag/b11429), CPU x64, и загружается официальная [Qwen3 4B Q4_K_M](https://huggingface.co/Qwen/Qwen3-4B-GGUF), 2 497 280 256 байт. Ревизия `bc640142c66e1fdd12af0bd68f40445458f3869b`; SHA-256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`. Рекомендуется от 8 ГБ оперативной памяти. Устанавливать Ollama или Python не требуется. Веса не входят в установщик. Увеличенный размер Windows-модели согласован отдельно; Android/macOS сохраняют прежнюю модель и ограничение 2 ГБ.

На Android сначала используется GPU; при ошибке инициализации или генерации обработка повторяется на CPU. macOS и текущий Windows-движок используют CPU. Модель загружается в фоне, после импорта её память освобождается. В чате видны текущий этап, номер фрагмента и кнопка отмены. На Android/macOS отмена во время загрузки движка завершается после возврата из его инициализации; на Windows завершается отдельный процесс в Job Object.

Описание с уже оформленным рецептом используется напрямую. Иначе приложение получает доступные субтитры через [youtube_explode_dart](https://pub.dev/packages/youtube_explode_dart), предпочитая русский язык, затем английский; для одного языка предпочитает авторские субтитры автоматическим. Это не официальный API YouTube: доступ может зависеть от сети, региона и ограничений видео. Звуковая дорожка не скачивается и не распознаётся.

Длинный текст делится на фрагменты с небольшим перекрытием и отдельным контекстом. Максимум — 60 000 символов, без молчаливого обрезания конца. Для продуктов и шагов модель указывает номера подтверждающих строк; несуществующие номера отбрасываются. Для шагов используются оригинальные строки, а не непроверенный пересказ модели. Количества, которых нет в подтверждающих строках, помечаются «количество не указано». Таймкоды, исходный текст и точная присланная ссылка сохраняются. Эти проверки уменьшают ошибки, но не доказывают смысловую правильность ответа: карточка остаётся редактируемой и требует проверки.

С включённым локальным ИИ текст и ссылки YouTube обрабатываются на устройстве, даже если указан адрес сервиса. Для сайтов сохраняется прежний режим импорта. Сервис может использоваться для видео при выключенном локальном ИИ. Веса и настройки модели не синхронизируются через Яндекс Диск; готовые рецепты входят в общую базу.

## Дополнительный сервис импорта

Python 3.11+:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r backend/requirements.lock
pip install --no-deps -e ./backend
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Или Docker из корня:

```bash
docker build -f backend/Dockerfile -t recipe-vault-importer .
docker run --rm -p 8000:8000 --env-file backend/.env recipe-vault-importer
```

Перед запуском Docker скопируйте `backend/.env.example` в `backend/.env` и настройте значения. Docker читает env-файл, обычный uvicorn использует переменные окружения.

В настройках приложения укажите адрес сервиса. На Android в домашней сети — `http://<IP-компьютера>:8000`; `localhost` на телефоне обозначает сам телефон. Для эмулятора Android — `http://10.0.2.2:8000`. На компьютере с запущенным сервисом — `http://127.0.0.1:8000`. Android допускает HTTP для такого локального сценария. Для сервиса вне домашней сети используйте HTTPS и `IMPORT_API_TOKEN`; соответствующий ключ задаётся в приложении.

API: `GET /health`, `POST /import` с JSON `{"content":"текст или ссылка"}`. Документация `/docs`. Сервис не хранит каталог и не получает токен Яндекс Диска. Запросы страниц ограничены по размеру и времени; локальные адреса блокируются, DNS-адрес фиксируется перед запросом, перенаправления проверяются отдельно.

Опционально установите модель в Ollama и задайте `OLLAMA_MODEL` (имя установленной модели) и `OLLAMA_URL` (по умолчанию `http://127.0.0.1:11434`). Это позволяет структурировать свободную речь и неформатированный текст. Без модели работает разбор по заголовкам, спискам, количествам и нумерации. Модель может ошибаться; карточку нужно проверять перед сохранением. См. [формат JSON в Ollama](https://docs.ollama.com/api/generate).

## Ограничения импорта

Сайты без разметки, страницы с защитой от автоматических запросов и рецепты внутри изображений могут потребовать ручного ввода. Субтитры и описание YouTube бывают недоступны: приложение не скачивает и не распознаёт звуковую дорожку. В этом случае сохраняется черновик со ссылкой. Неизвестные количества, порции и время остаются пустыми.

Чат хранит предпросмотр текущей сессии; постоянное хранение начинается после «Сохранить в каталог» или «Сохранить черновик».
