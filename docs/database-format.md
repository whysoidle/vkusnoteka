# Как устроен recipes.json

Эта страница нужна для разработки и восстановления данных. Для обычного переноса книги используйте **Экспортировать recipes.json**, **Импортировать и объединить базу** или [синхронизацию](yandex-webdav.md).

Файл — JSON в UTF-8, версия схемы `1`. Он содержит рецепты и сведения об их изменениях. Пароли, токены и адрес дополнительного сервиса хранятся отдельно и в экспорт не входят.

## Пример записи

```json
{
  "schemaVersion": 1,
  "records": [
    {
      "id": "uuid-рецепта",
      "modifiedAt": "2026-10-08T18:00:00.000Z",
      "clock": {"uuid-устройства": 1},
      "deleted": false,
      "recipe": {
        "id": "uuid-рецепта",
        "title": "Сырники",
        "category": "Завтраки",
        "ingredients": ["Творог — 400 г", "Яйцо — 1 шт."],
        "steps": ["Смешайте ингредиенты.", "Обжарьте с двух сторон."],
        "servings": "2 порции",
        "time": "20 минут",
        "notes": "",
        "sourceUrl": "https://example.com/recipe",
        "sourceText": "",
        "photo": "",
        "tags": ["Домашнее"],
        "collections": ["На каждый день"],
        "favorite": false,
        "draft": false
      }
    }
  ]
}
```

`photo` содержит миниатюру JPEG в Base64, до 120 КБ до кодирования. `tags` и `collections` — списки строк. У старых записей этих полей может не быть; приложение подставляет пустые значения.

## Как сравниваются изменения

У каждого рецепта есть стабильный ID. В `clock` хранится счётчик правок каждого устройства: при сохранении устройство увеличивает свой счётчик.

Если одна версия включает все известные правки другой и имеет более высокий счётчик хотя бы одного устройства, она считается более поздней. Если два устройства независимо изменили рецепт, счётчики не позволяют выбрать одну «последнюю» правку — это конфликт.

При конфликте приложение сохраняет основную карточку и отдельную копию. ID копии имеет вид `<original-id>:conflict:<content-hash>`. Выбор основной версии и ID копии детерминированы: повторная синхронизация того же конфликта не должна создавать новые копии. Исходные ссылки сохраняются в обеих карточках.

## Что происходит при удалении

В записи остаются `id`, `modifiedAt` и `clock`, а `deleted` становится `true`, `recipe` — `null`. Это отметка удаления: без неё старое устройство могло бы вернуть удалённый рецепт.

Если удаление и редактирование произошли независимо, редактируемая карточка остаётся доступной. После объединения её можно удалить ещё раз. Служебные отметки удаления нельзя вычищать из JSON без согласования всех устройств.

## Как сохраняется файл

Приложение сначала полностью записывает файл `.pending`. При замене основного файла предыдущая копия сохраняется как `.bak`. Если чтение не удалось, проверяются оставшийся временный файл и резервная копия.

Неизвестная версия схемы не заменяется пустой книгой. При повреждении данных исходные файлы сохраняются для восстановления.

## Облако и совместимость

В Яндекс Диске основной файл находится в `/RecipeVault/recipes.json`, копии устройств — в `/RecipeVault/.devices/`. Они нужны для объединения одновременных изменений. Общий предел базы, включая фотографии, — 20 МБ.

При переносе книги лучше пользоваться средствами приложения. Ручная правка JSON без изменения `clock` может создать неоднозначный конфликт. Держите приложения на устройствах на одной актуальной версии, чтобы старый редактор не удалял неизвестные ему поля.

Код формата и объединения: [recipe.dart](../app/lib/models/recipe.dart). Сохранение и восстановление: [storage.dart](../app/lib/services/storage.dart).
