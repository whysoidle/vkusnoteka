# Вкуснотека 1.0.6 — локальный ИИ на Windows

В Windows x64 встроен CPU-движок llama.cpp b9380. Для локального распознавания не нужны отдельные Python-сервисы, Ollama или ввод адреса сервера. В настройках появился раздел «Локальный ИИ»: скачать, остановить/продолжить загрузку, удалить модель, включить/выключить разбор. Изменения применяются сразу.

Windows использует официальную Qwen3 4B Q4_K_M, 2 497 280 256 байт (около 2,50 ГБ); модель скачивается отдельно от установщика. Рекомендуется от 8 ГБ оперативной памяти и 3,5 ГБ свободного места. Для Android/macOS остаётся прежняя Qwen3 1.7B INT4 и LiteRT-LM, общий размер с моделью меньше 2 ГБ. Модель не попадает в базу рецептов или облачную синхронизацию. URL привязан к конкретной ревизии; после загрузки проверяются размер и SHA-256.

## Правила разбора

Windows использует те же инструкции, схемы JSON и проверку по исходнику, что Android/macOS. Количество проверяется рядом с названием ингредиента; числа в таймкодах или длительность действия не становятся количеством продукта. Неизвестные количества остаются неизвестными. Шаги берутся из подтверждённых строк исходника в исходном порядке. Ингредиенты нескольких опубликованных рецептов сохраняются раздельно и дословно, а схема каждого фрагмента ограничивает допустимые номера рецептов. Конец длинного видео не отбрасывается; повреждённый или усечённый фрагмент требует проверки. Исходный текст и ссылка сохраняются при ошибке или отмене.

Параметры Windows: контекст 8192 токена, максимум ответа 2048 токенов на фрагмент, temperature 0, top-k 40, top-p 1, min-p 0, seed 42. Используется тот же ChatML с закрытым пустым блоком thinking, что на других платформах. История разных фрагментов не объединяется. Эти параметры уменьшают произвольность ответа, но не гарантируют безошибочное распознавание; карточку нужно проверять.

## Ресурсы и упаковка

Движок запускается на время импорта, слушает `127.0.0.1` на свободном порту и требует новый случайный ключ для каждого запуска. Соединение обходит системный HTTP-прокси. Вес модели читается из локального файла; автоматическая загрузка движком выключена. Ответ ограничен по размеру и времени.

Windows создаёт процесс приостановленным, добавляет в Job Object с `KILL_ON_JOB_CLOSE` и затем запускает. Отмена, ошибка, завершение импорта и закрытие окна освобождают процесс, модель, сетевой клиент и нативные handles. Аварийное завершение приложения тоже закрывает job и его дочерние процессы. Поздняя отмена старого задания не завершает новый импорт.

`scripts/build-windows.ps1` скачивает закреплённый официальный CPU-runtime, проверяет SHA-256, включает сервер, DLL, Visual C++ runtime и лицензии в `LocalAI` внутри установщика и portable ZIP. Идентификаторы и пути к базе/паролям сохранены.

## Проверки

GitHub Actions дополнительно собирает и запускает нативный тест жизненного цикла Windows-процесса и проверку настоящей модели через общий Dart-декодер. Проверяются русские аргументы, отмена, закрытие и повторное освобождение handles, четыре ингредиента с точными количествами и неизвестным количеством молока, время и порции, отдельные карточки двух рецептов и исключение рекламы.

Результаты сборки и контрольные суммы фиксируются после завершения Actions. Ручная проверка окна приложения на физическом Windows-компьютере выполняется отдельно.
