# Версия 1.0.0

Выпуск от 9 октября 2026 года. 133 теста Flutter и 23 теста сервиса прошли; статический анализ Flutter без замечаний. Общий Flutter-проект имеет версию `1.0.0+10`; дополнительный Python-сервис — `1.0.0`. База рецептов сохраняет прежний формат. Изменения общей логики действуют на Android, Windows и macOS; оформление платформ не смешивается.

## Файлы и обновление

- Android: `dist/RecipeVault-Android-1.0.0.apk`. Установите поверх прежнего приложения. Подпись сохранена, versionCode повышен до 10; каталог и настройки остаются в существующем хранилище.
- macOS: `dist/RecipeVault-macOS-1.0.0.dmg` или ZIP с универсальным приложением arm64/x86_64. Закройте старую версию и замените приложение в Applications.
- Windows: исходники 1.0.0 и `scripts/build-windows.ps1`. Готового EXE в этом выпуске нет: доступна только macOS, Windows-машины и удалённой CI-среды нет. Скрипт подготовлен для создания установщика, portable ZIP и SHA-256, но его выполнение на Windows ещё не проверено.
- Исходники всех платформ и сервиса: `dist/RecipeVault-Source-1.0.0.zip`. Подписи, пароли, локальные SDK, модель и кеши сборки исключены.

Для сборки Windows установите Flutter 3.47.6, Visual Studio с компонентами Desktop development with C++ и Inno Setup 6. Из корня распакованных исходников выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1
```

Скрипт читает версию из `app/pubspec.yaml`, включает Visual C++ Runtime, создаёт `RecipeVault-Windows-1.0.0-Setup.exe`, `RecipeVault-Windows-1.0.0-Portable.zip` и контрольные суммы. В репозитории также подготовлена сборка GitHub Actions на `windows-latest`.

## Исправления

- HTTP-импорт прерывает свой запрос при отмене, сохраняя возможность следующего импорта через тот же клиент. Ответы сайта и сервиса ограничены 3 МБ. Ошибки HTTP возвращают карточку для ручного заполнения без ожидания закрытия ответного потока.
- Завершённые этапы загрузки модели, проверки SHA-256, YouTube, локального ИИ и Windows OCR снимают обработчики отмены. Ошибка одного обработчика не мешает остальной очистке. Изоляты, порты и сетевой клиент закрываются при ошибках.
- Освобождение AppController закрывает текущий клиент синхронизации и OAuth; после закрытия контроллера новые запросы и таймеры не создаются. Уже начатые записи пользовательских правок не отбрасываются.
- Одновременный локальный разбор не перехватывает канал прогресса уже выполняемой операции.
- Android: удаляются обработчики каналов и отложенные сообщения при закрытии Activity. Рабочие очереди OCR и ИИ останавливаются; нативный ИИ получает отмену. Признак отмены фиксируется для конкретного результата, чтобы следующий импорт не изменил его задним числом.
- Windows: OCR-процесс ограничен 60 секундами, снимает обработчик отмены и закрывает процесс; stdout/stderr обрабатываются совместно. Установщик получает версию приложения автоматически.
- macOS: временные Foundation-объекты освобождаются после каждого фрагмента субтитров. Упаковка восстанавливает только личную ad-hoc подпись верхнего пакета после инкрементального обновления PDFium, предварительно проверяя каждую вложенную библиотеку. Для других типов подписи автоматического переподписания нет.
- Python-сервис: HTTP-сессия YouTube закрывается при успехе и исключении. Блокирующие запросы субтитров имеют тайм-ауты подключения/чтения 10/20 секунд, поскольку отмена coroutine сама по себе не останавливает рабочий поток.

## Проверка памяти

Flutter: 10 циклов полного приложения и по 5 экранов в каждом цикле, отдельно для Android, Windows и macOS — 150 открытий/закрытий страниц. Проверяются настройки, редактор, карточка рецепта, импорт документов и режим готовки. [leak_tracker](https://github.com/dart-lang/leak_tracker/blob/main/doc/leak_tracking/OVERVIEW.md) отслеживает освобождение объектов. Дополнительно слабые ссылки на AppController, TextEditingController, ScrollController и AnimationController проверяются после пяти запросов полной GC через Dart VM Service. Очередь FakeAsync обрабатывается между запросами GC, чтобы не принимать отложенные тестовые ответы за ссылки приложения. Системный буфер обмена имитируется; пользовательский буфер не читается.

Освобождены все отслеживаемые слабые ссылки: Android — 5971, Windows — 6381, macOS — 6921. Ссылки могут относиться к одному объекту несколько раз; это не число уникальных экземпляров. Неосвобождённых контроллеров в проверенном сценарии не обнаружено.

Команда полного прогона:

```bash
cd app
flutter test --enable-vmservice
flutter analyze
```

Без `--enable-vmservice` выполняются обычные проверки dispose; дополнительная проверка слабых ссылок требует VM Service. Экспериментальный общий режим notGCed в leak_tracker заменён прямой проверкой GC: он не завершался корректно при ожидании очереди FakeAsync.

Нативный macOS LiteRT-LM проверен отдельным процессом на синтетическом рецепте: три загрузки движка, реальный разбор и удаление всех C-дескрипторов. Apple `leaks --atExit` с MallocStackLogging: **0 leaks, 0 total leaked bytes**. Без MallocStackLogging остаточный RSS после трёх циклов: 1 602 600 960, 1 607 204 864 и 1 076 543 488 байт. Возврат RSS к начальному значению не подтверждён, устойчивого роста между циклами не наблюдалось. Эта проверка не доказывает отсутствие любых утечек при других действиях и длительной работе.

Проверки интерфейсов Android и Windows выполнялись в Flutter-тестах на Mac. Android-устройство не подключено; нативная память Android на телефоне и Windows на реальном компьютере не профилировалась. Пользовательская база, ключи Яндекса и облако в тестах не используются.

## Размер

Android APK — 158 840 442 байт. Консервативная сумма распакованного APK, модели и рабочей копии OCR-данных — 1 150 043 458 байт.

Установленное macOS-приложение без повторного подсчёта символических ссылок — 216 452 981 байт; с моделью — 1 193 637 013 байт. Обе суммы меньше 2 ГБ без растущего каталога рецептов и системных данных. Наличие модели в памяти не входит в размер установленного приложения.
